# 目标值走两线框架：够用线必有、竞争线可选

竞品调研（#5）证实端到端时延与对讲喇叭 SPL 的竞品数据是行业空白，工单 #9 由此问「没锚点的目标值从哪来」，候选是四条并列路径（自测竞品/物理正推/借标准/借感知文献）。查证后发现前提有误：缺的只是「竞品做到多少」，而「人耳多少才够」两项都有外部可引的刻度（G.114 时延阶梯、Lowell 环境噪声 +10/+15 dB）。定案：四路径不并列——**感知文献/标准刻度是翻译字典**（把意图册的用户可观察效果翻译成数值档，选档权归意图措辞），**物理正推是既有的物理包络层**，**竞品数据只喂竞争线**。每条目标值 = 够用线（意图 × 字典对撞物理包络）必有；竞争线（竞品实测 + 可感知差距）只挂卖点指标。买竞品自测的触发判据仅两条：①卖点指标且竞品数据空白；②物理翻译模型缺外部校准点——但校准点不强制竞品机，任意在手真机可充。

## Considered Options

- **四路径并列、按优先级排序取数**：把回答不同问题的来源（够用/可行/市场）混成同一问题的备选答案，「什么情况下必须自测」永远答不清。否决。
- **物理正推自足、不要求外部字典**：正是工单担心的「自嗨的数」——够用判据自己发明，评审桌上「为什么是这个数」答不上来。定为红线：判据必须外部可引，字典空白则放弃绝对目标值（差值化或参考期望，借 #8 四出路形状），自定绝对数永远不合法。
- **本次为示范机型安排竞品自测**：示范机型两项都有够用线字典，卖点决策未发生，此刻自测没有任何决策等它——违反 task 工单靠解锁决策挣位置的原则。不做，触发判据写进方法，将来卖点拍板那一刻再立 task。
- **「依据」做成条款模板第三槽位**：#6 刚钉死「档 × 值」两槽正交；依据是对数字的标注（一条条款多个数、各有各的依据），与槽位不同构。降为写作规则（NOTES 硬规则）。

## Consequences

- 借字典必须做口径迁移核查：一行「字典出处 + 迁移前提」，迁移不了又验证不了的落成前提行，吃 #8 验证状态四件套。G.114 借到摄像机上的迁移前提就一条——对讲交互性与通话同级；纯喊话场景可放宽到 400 ms
- 意图册维度的取值域直接用字典档名（「像打电话」→150 ms，「能对上话」→400 ms+知情），逼意图措辞钉到能查表的精度；此规则连同 P.340 Category 表、G.114 阶梯两本字典，接口移交双讲 Category 工单（#10）
- 竞品自测本身是一条测法，过 #8 可复现性三问才算数；竞争线赢不了可感知差距（差距量也查字典，如拾音距离按 +6 dB 减半规则）就回落够用线，不写「略优于竞品」
- 术语（够用线/竞争线/翻译字典/依据标注/校准点）入 CONTEXT.md「目标值来源」节；依据标注入 NOTES 硬规则
