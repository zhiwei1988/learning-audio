# 规格条款套统一模板，门槛不单列为独立形状

推导交出的最终规格条款该长什么样：门槛（单值）、分层承诺（同一功能按条件分档，各档独立物理依据）、带前提的承诺（目标值+待验证前提清单）三选一，还是可组合？改为**统一条款模板**——「档」（分层承诺）与「值」（带前提的承诺）两个正交、可各自为空的槽位；两槽都空即退化为单一门槛值，门槛因此不再单列为独立形状。理由：放音的真实样例（3.5 m 必达 / 5 m 目标+前提）本身就是「档内的值又带前提」，若两种形状不能组合，方法交付时会反复卡在「这条该用哪个形状」上。

## Considered Options

- **各条款各选形状，不强求统一结构**：保留门槛/分层/带前提三种并存。否决：放音样例已经证明分档与带前提要同时出现，三选一覆盖不了真实条款。
- **保底值强制**：带前提的承诺必须同时给保底与目标两个数。否决：不是所有「必填×只能拍范围」的维度都天然有可交付的保底台阶，强制会逼出编造的数字，违反 `NOTES.md` 的外推标注硬规则；改为可选。
- **「对讲」整档挪出分层承诺表、并入双讲组**：让分层承诺表只留监听/提示音/语音放音三档。否决：对讲距离（1.5 m）的物理依据来自拾音/放音物理包络层的 min 运算，和另外三档同源，理应留在同一张表；只挪走会让分层承诺表缺一个最直觉的档。改为「对讲」距离档留在分层承诺表，双讲质量条款（ERLE Category、时延预算）另开一组，两者通过距离数字互相引用，不合并成一条。

## Consequences

- 前提清单的验证状态字段（待验证/已验证/已证伪）与验证归属不在本决定内定义，下放给「每条规格如何绑定测法」工单（issue #8）
- 四档命名（监听/提示音/语音放音/对讲）成为方法固定资产，写入 `CONTEXT.md`；后续机型缺档留空占位，不重新拟名
