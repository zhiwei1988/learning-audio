# 双讲当结算台，而非三组排序推导

推导拾音/放音/双讲三组规格时，两条显然的组织方式——(a) 三组独立推导 + 末端冲突表、(b) 用耦合决定三组先后——都被否了，改为**分层结算**：拾音、放音先各自独立推出物理包络（输出取舍曲线，不是工作点），双讲作为**结算台**在曲线上选工作点、同时结算回声账与端到端时延账，预算墙最后进场。

依据：全课挖掘 24 个共享旋钮证实，**所有已证耦合都路过双讲（回声）或整机级预算账，拾音↔放音 之间没有直接耦合**——三组在耦合图上不对等，双讲是枢纽。(a) 把冲突攒到末端，回退深且「该退谁」无原则；(b) 假设双讲永远是主导约束，但店铺样本（issue #2）里双讲恰是让步方——顺序随意图翻转，(b) 得逐场景重新论证顺序。

## Consequences

- 层序固定（包络 → 结算 → 预算），场景差异全部收敛进**退让顺序**（产品意图册必填维度）；一套退让程序、两处调用（issue #7 设计）
- 层间接口是曲线不是点：结算失败沿曲线滑动找新工作点，第一层不重跑
- 端到端时延条款归双讲组——对讲自然 = 回声行为 × 时延，硬约束式 `播放缓冲 + 空气路径 + 采集缓冲 < AEC 尾长` 把两本账钉在同一张结算桌上
- 耦合清单 `reference/coupling-inventory.md` 是方法固定资产；术语见 `CONTEXT.md`「推导骨架」节；决策全文与八问过程见 issue #3
