# 提问清单是规格的投影，不是第二份文档

立项期规格的真实用途之一是变成向方案商的提问清单（工单 #13）。定案：清单 = 规格文档上的**机械投影**——两个来源（转举证条款 + 执行方=方案商的前提行），每条带回链，**规格无根的问题不准入**：评审时想问方案商而规格里找不到根，说明规格漏了条款，先补规格再重新投影。**以选型对比为第一设计对象**（立项期发多家候选、回答横向对比），验收视图是同一条目库改措辞的免费副产品——能对比的条目（钉死口径+判定形式）天然能当验收条款，反之不成立。条款准入按「数据在谁手里」三分：转举证条款（数据只能由方案商产出）进核心区；平台约束型（数据在对方 NDA 报表里）以「按我方模板报数」进清单；物理包络绝对条款不进清单本体、只进背景段。

## Considered Options

- **独立编写 RFI 文档**：业界默认做法。但两份文档必然漂移，且清单里没根的问题永远暴露不了「规格漏条款」。否决。
- **物理包络条款以「请确认可行性」进清单**：方案商对我方物理推导的「确认」没有信息量——他既无激励也无数据去反驳，只制造虚假背书。物理包络的正确位置是背景段：它是对方回答其他条目的输入（对讲距离决定按什么 ERL 假设报 ERLE）。否决。
- **加权评分表对比多家**：权重这个东西方法里已经有了——意图册必填维度「退让顺序」；再造评分权重是同一信息记两遍、还会打架。定案为**逐条判定 × 退让顺序**：每家一张不达标清单，砍在退让顺序尾部的赢砍在头部的。否决评分表。
- **探索性摸底题单列、不受回链约束**：所谓摸底题（「把音频算法占用按此模板填全」）都能改写成平台约束型「按我方模板报数」条目——模板即口径。真归不进去的问题是在报告入口向量或规格缺维度，回去补，投影规则不破。否决单列区。

## Consequences

- 条目六槽位：回链｜措辞（选型/验收双渲染）｜回答形状｜测量网格｜口径｜判定——五个是既有资产引用，新造只有「回答形状 + 测量网格」（形状库落 `reference/answer-shapes.md`，初始四行先例）
- **测量网格由我方出**：第 2/9 课反复证明 datasheet 各有各的测量条件，而归一化需要的换算条件恰恰是方案商最不写的——事后归一化在方法上不可行，只能事前钉格子
- **选型版不印够用线阈值**：阈值不是「缺了它对方没法回答」的输入，是我方决策信息——要数不给线，判定权留在桌子这一边；验收版（签约后）照常含阈值
- 劣质回答全局规则一条（清单前言）：不符回答形状 → 一轮定向追问（把形状再念一遍）→ 仍不合格记空白，空白进对比表
- 背景段准入判据：缺了它方案商无法正确回答；退让顺序、竞争线、保底值不出门
- 清单的排版（表现层）并入「规格文档最终排版与交付形态」雾——视图跟着本体的排版走
- 术语（清单投影/回答形状/测量网格/背景段）入 CONTEXT.md「清单投影」节
