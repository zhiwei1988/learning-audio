# 正式主观评测的最低执行门槛与成本：P.800/P.835/P.808 自建、送测、众包三条路

对应 GitHub issue [zhiwei1988/learning-audio#19](https://github.com/zhiwei1988/learning-audio/issues/19)（地图 #16 子工单）。

**结论先说**：P.800/P.835 的门槛比想象中"软"——标准本身没有给出统一的听音室认证费或器材清单，真正硬性的数字只有三个：P.835 要求**至少 32 名 naive 听音员**（§5.2.1）、P.800 Annex F（阈值法）要求**至少 6 人，推荐 12+**，以及 P.808 众包路径经同行验证给出的**每条件 96 票（8 人 × 12 次复现）**下限——三个数字来自三份不同文档，互不替代。P.808 众包变体不是"廉价替代品"而是 ITU 官方承认、有独立论文交叉验证的第二条路（众包 MOS 与实验室 MOS 的 PCC=0.962），但**代价是众包本身的地基在动摇**：本次核实时（2026-08-10）Amazon Mechanical Turk 官网已挂出"不再接受新客户"的横幅，microsoft/P.808 工具链文档里唯一详细写明操作步骤的平台事实上对新用户关闭，仅剩 Prolific 或自建面板可用。三条路的成本量级：国内找不到任何一份公开的免提/降噪主观评测报价单（第三方实验室这块是**认证行业公开但细分领域不公开**的典型情况，通信终端认证本身价格公开在万元量级，但专门做 P.835 人耳评测的实验室不挂价），而众包路径的结构性成本可以从 P.808 自己的票数要求和 Prolific 现行费率推出量级——是三条路里唯一能拿到一手数字直接算出总价的。行业合规侧，ETSI TS 103 740 引用的背景噪声质量门槛（N/S/G-MOS≥3.0）挂的是 **TS 103 106 这个客观算法模型的输出**，不是逐台产品的现场人耳评测；P.1100 系的语音质量条款干脆把方法论标成"非强制"。可信度地板落在六条清晰、可操作的判据上，见第 5 节，直接对齐 CONTEXT.md 的"双轨测法"框架。

## 1. P.800 / P.835 的最低执行门槛

### 1.1 听音环境

P.800 对"会话测试"（conversation-opinion）和"听音测试"（listening-opinion）分别规定了物理条件（Annex A.1.1、Annex B.1.1、B.4.1）：

- **录音/听音室**：容积不小于 20 m³（手持/耳机类），**不小于 30 m³（免提类）**；混响时间 <500 ms，推荐 200–300 ms；内部尺寸比例建议 5:4:3 以抑制驻波（P.800 §A.1.1.1）。
- **本底噪声**：无主动引入噪声时，上限为 **NC25/NR25**（约相当于住宅卧室、医院、图书馆的噪声水平）（§A.1.1.2.1）。
- **环境噪声（如需引入）**：按 Hoth 谱型，A 计权测量，典型 50 dBA，测量点在被试椅正上方 740 mm，"A"计权、"fast" meter（§A.1.1.2.2、§A.1.1.3）。
- P.835 §5.2.2 明确"音频呈现应遵循 P.800 的指引，包括听音系统、听音电平、测试时长与听音环境"——**P.835 本身不重新定义环境参数，全部借用 P.800**。

**一手来源**：ITU-T Rec. P.800 (08/1996) §A.1.1、§B.4.1，<https://www.itu.int/rec/T-REC-P.800-199608-I>；ITU-T Rec. P.835 (11/2003) §5.2.2，<https://www.itu.int/rec/T-REC-P.835-200311-I>。

### 1.2 评分员人数与筛选/训练

这是本次调研最反直觉的发现：**P.800 正文（Annex B，ACR 方法）没有给出固定的听音员人数下限**——只给了筛选条件（未参与过电路评估工作、6 个月内未做过任何主观测试、1 年内未做过听音测试、未听过同一批句子），人数留给实验设计者按统计功效自行决定。唯一给出显式人数下限的是 **Annex F（阈值法）：最少 6 人，推荐 12 人以上**（§F.6）。

P.835 则给出了**全篇唯一的强制人数**：

> "At least 32 naïve listeners shall participate in the tests." （P.835 §5.2.1）

且要求听音员为测试语言的母语者、过去 3 个月内未参与过任何主观实验。

训练方面，P.800 §A.4.3/B.4.6 要求书面+口头说明、一段"预备清单"熟悉流程，但明确禁止暗示样本范围（"No suggestion should be made to the subjects that the preliminary samples include the best or worst"）；P.835 Appendix II 给出了完整的指导语样板，含 8 条练习 + 4 组 18 条正式测试 × 2 个 session（约 44 分钟总时长）。

**一手来源**：ITU-T Rec. P.800 §B.4.4、§F.6、§A.4.1；ITU-T Rec. P.835 §5.2.1、Appendix II。

### 1.3 素材要求

- **语料**：简短、有意义、彼此无关联的句子（非技术性文献/报纸来源），单句时长 2–3 秒；每组 2–5 句；组合成 5 或 10 组一份的清单（P.800 §B.1.4）。
- **说话人**：至少 2 男 2 女（平衡因子），DCR 方法要求至少 4 位说话人 × 2 个句子样本 = 8 条语料构成语料库（P.800 §B.2.2、§D.2.1）。
- **录音室**：容积 30–120 m³，混响 <500 ms（推荐 200–300 ms），本底噪声 <30 dBA（P.800 §B.1.1，比听音室本身的 NC25 略宽松）。
- **电平**：窄带语音标定为相对满量程 −26 dBov（±0.5 dB）；信噪比（P.56 有效语音电平 / 心理声学加权噪声）> 40 dB（P.800 §B.1.5、§B.1.7）。
- **条件数**：P.800 没有规定固定条件数，由实验设计（拉丁方/Youden方/平衡不完全区组）决定；P.835 §5.1.3 明确要求参考条件需**独立覆盖信号维度与背景维度的整个量表范围**——即至少要有一组"固定 SNR、变 MNRU"和一组"固定 MNRU、变 SNR"的锚点网格（图 1–3 给出的示例是 5 个 MNRU 档 × 5 个 SNR 档）。
- **锚点条件**：P.800/P.835 统一用 **MNRU（P.810 调制噪声参考单元）**做信号维度锚点，用 **SNR** 做背景维度锚点；P.835 §5.1.3 的图示显示 Q 值范围 8–40 dBQ，SNR 范围 0–40 dB 是常用网格。

**一手来源**：ITU-T Rec. P.800 §B.1、§B.2、§D.2.1；ITU-T Rec. P.835 §5.1。

### 1.4 统计判定方法

P.800 §A.4.5/§B.4.7："置信区间应被计算，显著性检验用常规方差分析（ANOVA）技术执行"；DCR 方法额外要求 **Tukey HSD（Honestly Significant Difference）事后多重比较检验**（Annex D.3）。P.835 §5.3.1 把方法列全："t 检验、Tukey 检验、ANOVA 或 MANOVA，视实验设计而定"。均未规定固定的显著性水平（α）或效应量门槛——**判定标准由实验设计者自定，标准本身只锁工具箱不锁阈值**。

**一手来源**：ITU-T Rec. P.800 §A.4.5、§B.4.7、Annex D.3；ITU-T Rec. P.835 §5.3.1。

## 2. P.808 众包变体的门槛与可信度

### 2.1 工具链是否开放可用

microsoft/P.808（GitHub）是 P.808 的开源实现，实测支持 **ACR / DCR / CCR / P.835（噪声抑制专用四维评分）** 四种流程，内置听力自筛（数字三元组测试）、环境适宜性测试（MJNDQ 成对比较法）、陷阱题（trapping question）、金标准题、耳机佩戴检测（通过 WebRTC API 探测已连接音频设备，实测成功率仅 **40.1%**——"未检出耳机"不等于"没戴耳机"，这条过滤器本身不太可靠）。

**关键变化（本次核实，2026-08-10）**：microsoft/P.808 的实现原生跑在 Amazon Mechanical Turk 之上，而 **mturk.com 首页目前挂着横幅**："*Amazon Mechanical Turk is no longer accepting new customers. We recommend existing customers migrate to a third-party solution.*" 多家科技媒体（TechCrunch、The Register、SiliconANGLE 等，2026-07 报道）交叉印证 AWS 已定 **2026-07-30** 为新客户/新工作者停止接入的日期，已有账户可继续使用但平台不再投入新功能。这意味着：**从零开始的新项目已经无法按 P.808 文档的默认路径（AMT）走通**，必须改用文档同时列出的备选——**Prolific** 或自建面板基础设施。

### 2.2 众包平台依赖

microsoft/P.808 GitHub 文档明确列出三选一："使用 Amazon Mechanical Turk (AMT)、Prolific，或用一个专属的自有工作者面板做远程测试"——即工具链本身对平台有一定解耦，只是官方示例脚本历史上是围绕 AMT 写的。

### 2.3 中文语料可行性

P.808 §6.3.5 明确列出的听音员筛选条件与语言无关（听力、母语流利度、无重复参与），标准正文没有任何语言限制条款；Note 甚至专门提到"可以邀请非母语工作者，但建议为每个语言熟练度分组单独跑一次实验以控制方差"。工具链层面，`babaknaderi/P.835`（P.808 团队另一仓库）和 `microsoft/P.808` 的陷阱题设计方法（§6.3.8）要求"用与语料相同语言录制的说话人"生成陷阱刺激——**中文语料在方法论上没有障碍，但工具链的现成陷阱题/训练素材库是英文的，中文项目需要自己按 §6.3.8 的步骤重新生成一套**。

### 2.4 与实验室 P.800 的相关性（一手对比数据）

Naderi & Cutler（INTERSPEECH 2020）用 ITU Supplement 23（P.800 实验室数据集，G.729 窄带编解码器降质，200 个文件、50 个条件）做基准，跑了一次 P.808 众包实验，96 票/条件，与实验室 MOS 比较：

> **PCC = 0.962，SRCC = 0.923，RMSE = 0.237**（一阶映射后降至 0.214）（论文 §4.1、Figure 3）

**复现性实验**（§4.2）：同一份 700 条 INTERSPEECH DNS Challenge 测试集，五个不同的日子、每天换一批评分员（平均 89 人/次），跑五次 P.808：

> 绝对 MOS 的跨次一致性 **ICC = 0.719**；差值分数 DMOS（= MOS_测试条件 − MOS_噪声基线）的跨次一致性 **ICC = 0.907**（论文 §4.2）
> 原文："*bias observed between MOS values in different runs is a well-known and common behavior in the subjective tests. Using the DMOS successfully removed that offset.*"

**过滤机制的实测效果**（论文 Table 3）：陷阱题过滤后 ICC_MOS 从 0.063 提升到 0.705（显著），环境测试过滤后从 0.451 提升到 0.685，全部条件叠加后达到 0.719（MOS）/0.907（DMOS）；耳机检测过滤器**未观察到显著提升**（因为检出率只有 40%，样本量不足以下结论）。

**一手来源**：Naderi & Cutler, *An Open source Implementation of ITU-T Recommendation P.808 with Validation*, INTERSPEECH 2020, arXiv:2005.08138，§4.1、§4.2、Table 2、Table 3、Figure 3、Figure 4。

## 3. 三条路的成本量级与可信度差异

### 3.1 自建听音小组

标准给出的物理门槛可以直接翻译成建设清单，但**本次调研没有找到任何公开的一手报价**（既非 ITU/ETSI 文档职责范围，也没有搜到国内隔声室工程或声学测量仪器的公开报价单可直接引用）——以下是从 §1 门槛反推的结构性成本项，**明确标注为推导而非查得的数字**：

- 一次性建设：满足 P.800 §B.1.1 的听音室（30–120 m³、RT<500 ms、本底 <30 dBA）需要专业声学装修；P.835 §5.2.1 要求的 32 名 naive 听音员意味着需要建立一个可持续复用的招募渠道（不能用同一批人反复测，P.800 §B.4.4 c 款禁止"听过同一批句子"）。
- 每次边际成本：32 人 × 单次测试报酬 + 场地占用 + 至少一名熟悉 ANOVA/Tukey HSD 的统计分析人力（P.800 §A.4.5、P.835 §5.3.1 要求的判定方法）。
- **可信度**：这是唯一能做到与 ITU 标准逐条对齐、无平台依赖风险的路径，前提是真的按 P.800/P.835 门槛执行（32 人、锚点网格、ANOVA）——如果为省钱缩水任何一条（人数、锚点、筛选），就跌出"实验室级"的定义，见第 5 节。

### 3.2 第三方实验室送测

**国内实验室核查结果**：

- **中国计量科学研究院（NIM）声学实验室**：官网明确其业务是"计量"——声压基准、听力零级基准、超声功率基准、水声基准的**校准装置**维护，**不提供 MOS 主观评测服务**（一手核实，官网页面直读）。
- **中国泰尔实验室（CTTL，中国信通院下属）**：官网泛泛提及"性能测评、用户体验"等能力，但《产品检测收费办法》（TLC-GK-05-004-4，2025-10-13 实施，一手全文核实）42 页收费表覆盖通信线缆、电源、蓄电池、配线架、天线等 24 大类，**目录中没有任何语音质量/主观评测/免提终端声学测试的条目**——即这份公开报价单证明泰尔实验室至少在这份文件覆盖的业务范围内不卖 P.835 式人耳评测服务。它给出的是**相邻行业的价格量级锚点**：同类通信终端产品认证检测费落在**5,000–50,000 元/项**区间（如数字移动电话机基础制式检测 35,000 元，每加一个制式 +10,500 元；新技术产品全项认证 50,000 元/认证单元，多单元有折扣）。这不能直接当作免提声学测试的价格，但可以作为"国内通信终端类第三方检测收费的数量级"参照。
- **HEAD acoustics 中国**：官网确认其提供语音质量测试与优化的"工程咨询服务"（consulting services），但页面未公开任何报价，需直接询价（二手确认，未获取到价格数字）。
- **结论**：国内找不到任何一份公开挂价的 P.835/免提声学主观测试报价单——这是**认证行业的常态**（B2B 询价制），不是调研深度不够。唯一能确认的是：这类服务存在（HEAD acoustics 中国有对应业务线），价格需要一事一议。

### 3.3 众包（P.808）

这是三条路里唯一能拿到足够一手数字、自己把总价算出量级的路径：

- **票数要求**：P.808 §6.3.1.3 明确"ACR 众包实验中，每个刺激至少 8 人评分，每个条件至少 96 票（引自 P.863 Appendix II）"；DCR/CCR 单次会话时长约为 ACR 的 2 倍，P.835 式（信号+背景+整体三维）约为 ACR 的 3 倍（P.808 §6.2.2 Note 2）。
- **平台费率（Prolific，2026-08-10 核实的官方定价页）**：官方最低时薪 £6/$8，推荐至少 £9/约 $12/小时；企业账户平台服务费 42.8%（学术/非营利账户 33.3%）叠加在参与者报酬之上。按官方给出的算例：30 分钟任务、$12/小时报酬 → 每人 $6 + 42.8% 服务费 $2.57 = **每参与者 $8.57**。
- **粗略换算**：若一个 P.835 式评分任务（10 条刺激/任务，参考 Naderi 论文 §3.2.2 的默认设计）耗时与 Prolific 算例的半小时任务量级相当，每条件需要 96 票、每人可评估多条刺激（论文默认设计是每人一份任务只评一组，10 条刺激 × 24 人 = 240 次评分覆盖一个条件绰绰有余，Naderi 论文实测用的正是"10 刺激/任务、24 众包工作者/刺激 = 96 票/条件"这个配置，见 P.808 §6.2.2 Note 1）——**一个条件的评分成本量级在几十到一百余美元**，比自建听音室的固定资产投入低一到两个数量级，这与 Naderi 论文原话一致：

> "*It has also been used in the INTERSPEECH Deep Noise Suppression challenge, which made the challenge possible to do with similar quality but with much lower costs and effort to administrate. The cost is low enough that it can even be part of a daily machine-learning development cycle.*"（论文 §5 结论）

- **可信度**：§2.4 已给出 PCC=0.962 的实验室相关性数据——但这个相关性是在**满足 P.808 全部质控机制**（陷阱题+环境测试+96 票/条件）的前提下测得的；简化任何一环，相关性会退化（见 Table 3 的 ICC 对比）。

## 4. 免提/IPC 行业标准合规：强制实验室级，还是客观指标为主？

结论：**客观指标为主，主观测试要么是"非强制"选项，要么被折叠进客观算法模型的输出里，不要求逐台产品跑真人面板。**

- **ETSI TS 103 740**（§6.9.2）要求背景噪声质量 N-MOS-LQOw ≥3.0、S-MOS-LQOw ≥3.0、G-MOS-LQOw ≥3.0，但这三个分数是**引用 ETSI TS 103 106 这个客观评分算法模型**算出来的——TS 103 106 本身是"把一段带噪录音换算成三个分数"的信号处理模型，不是让人坐进听音室打分（详见 `reference/research-handsfree-spec-standards.md` §3.7，一手核实）。命名规则本身就是证据：**"MOS-LQO"里的 LQO = Listening Quality Objective**（区别于 P.800.1 定义的 LQS = Listening Quality Subjective），行业标准挑的是这条客观分支。
- **ITU-T P.1100**（§11.5.1）语音质量条款写的是 "MOS-LQON ≥3.0（**Appendix I，非强制方法**）"——标准原文自己把这条标成非强制（同上引用文档 §2.1 对照表已核实章节号）。
- **ITU-T P.1130**（子系统级规格，06/2015 现行版）在麦克风 SNR 分级表这类真正依赖真人判断的条目上，四档车速的数值原文直接写 **"FFS"（For Further Study）**——即行业标准写到这一步时自己都没有真人评测数据去定案，遑论要求下游产品逐台送去做实验室级 P.800/P.835（同上引用文档 §3.5）。
- P.808 自己的 Scope 也承认这个位置关系：众包/客观方法是对"标准化实验室方法（P.800、P.835）"的**补充**而非替代，两者服务不同目的——这进一步印证行业里"实验室级真人主观评测"是金标准但非日常合规门槛，真正逐台产品跑的是客观预测算法（P.862/P.863/TS 103 106 这类"-LQO"体系）。

**一手来源**：`reference/research-handsfree-spec-standards.md` §2.1、§3.2、§3.5、§3.6（该文档已对 ETSI TS 103 740 V1.4.1、ITU-T P.1100 (10/2008)、P.1130 (06/2015) 做过一手全文核实，本次直接引用其章节号结论，不重复下载）；ITU-T Rec. P.808 (06/2021) §1 Scope（"crowdsourcing-based methods are not expected to replace laboratory testing"）。

## 5. 简化变体的可信度地板——对齐"双轨测法"框架

CONTEXT.md 定义的"双轨测法"（双讲组专用）：内部轨（自推导近似法，仅用于排序与回归）与对外轨（转举证或第三方实验室）并行，**内部轨结果在交叉标定完成前不得写进对外文件**。本节把这个框架从双讲场景推广到主观评测通用场景，给出六条可操作的地板判据——**任一条不满足，测出的数字就只能进内部轨（排序/回归），不能进对外文件**：

1. **评分员数量低于验证过的下限**。P.835 自己的硬性下限是 32 人（§5.2.1）；P.808 众包路径经同行验证的下限是 8 人/刺激、96 票/条件（P.808 §6.3.1.3，且这正是 Naderi 论文测出 PCC=0.962 时用的配置）。低于这个数字，没有任何一手证据支持"这个分数能代表总体听感"。
2. **没有锚点/差值设计**。P.835 §5.1.3 要求参考条件（MNRU × SNR 网格）覆盖量表两端；Naderi 论文的核心发现是**绝对 MOS 跨次一致性只有 ICC=0.719，而差值 DMOS 达到 0.907**——没有锚点或不做差值化，测出的绝对分数换一批评分员、换一天就可能对不上，只能在**同一批语料、同一次会话内部**做相对排序，不能拿绝对数值去跨会话/跨机型比较，更不能对外承诺。
3. **没有听音员筛选**。P.808 §6.3.5 的最低筛选是：听力损失 <25dB@8kHz 以内所有频率、母语/母语级流利、未参与近期同类测试、未听过同一语料。省略这条，连 P.808 自己定义的"及格众包测试"门槛都够不上。
4. **没有可靠性检验机制**。P.808 §6.3.8 要求陷阱题+金标准题；Naderi 论文 Table 3 实测显示，过滤掉答错陷阱题/金标准题的数据后 ICC_MOS 从 0.063 跃升到 0.705——即**不做这层过滤，数据里混着大量不专心/作弊的评分，噪声大到无法判定**。
5. **听音环境不受控**。P.800 §B.1.1/§B.4.1 的听音室要求（RT<500ms、本底<30dBA）或 P.808 §6.3.2 的众包环境适宜性测试（<43dB(A) 或 MJNDQ 成对比较自检）二选一必须满足其一。在嘈杂开放办公室或未经检验的家庭环境里随手录的对比测试，属于两个标准都明确排除的条件。
6. **单次不可复现**。即使 1–5 条全部满足，Naderi 论文的复现性实验（同一语料、五个不同日子、五批不同评分员）显示即便是标准动作的 P.808 流程，跨次绝对 MOS 依然会漂移（ICC=0.719）——**只跑过一次、没有重复验证过的内部测试结果，默认视为"待复现"，不构成对外背书的证据链**，这与 RESOURCES.md 里"a_H,S,DT 流程需送一次第三方实验室做交叉标定"的既有结论（#12 遗留待办）是同一个逻辑。

**推广后的判定规则**：满足全部六条 → 至少达到"可信的众包/简化实验室"水平，可以作为对外文件的支撑证据（仍建议注明测法与样本量，遵循"依据标注"惯例）；六条中任一条不满足 → 该测法归入内部轨，仅用于内部排序/回归/迭代验证，写进对外文件前必须先补齐缺口或转成"转举证"条款（让方案商按 X 测法提交第三方报告）。这与 CONTEXT.md「不可测四出路」（差值化 → 转举证 → 参考期望 → 删）是同一套底层逻辑在主观评测场景的实例化。

## 6. 结论回应 issue 的五个问题

1. **P.800/P.835 最低执行门槛**：环境（听音室 30–120 m³/RT<500ms/本底<30dBA，P.835 借用同一套）、评分员（P.835 强制 ≥32 naive 听音员，P.800 ACR 无固定人数只有筛选条件，Annex F 阈值法另有 ≥6/推荐12+ 的独立下限）、素材（≥2男2女、5-10句/清单、锚点用 MNRU×SNR 网格）、统计（ANOVA + 置信区间，DCR 加 Tukey HSD，无固定 α 阈值）——见第 1 节。
2. **P.808 众包门槛与可信度**：工具链开源可用（microsoft/P.808），但原生绑定的 AMT 平台**已于 2026-07-30 停止接入新客户**（本次一手核实 mturk.com 官网横幅），需迁移 Prolific 或自建面板；中文语料方法论无障碍但陷阱题/训练素材需自建；与实验室 P.800 相关性 PCC=0.962（一手论文数据）——见第 2 节。
3. **三条路成本量级**：自建与实验室送测均缺公开一手报价（相邻行业锚点：国内通信终端认证 5,000–50,000 元/项）；众包路径能拿一手数字推算，单条件量级在几十到百余美元，比固定资产投入低 1–2 个数量级——见第 3 节。
4. **行业合规是否强制实验室级**：不强制。ETSI TS 103 740 挂的是 TS 103 106 客观算法输出（"MOS-LQO"命名本身即证据），P.1100 把真人测试方法标为"非强制"，P.1130 多处真人依赖的数值原文写"FFS"未定案——见第 4 节。
5. **简化变体可信度地板**：六条可操作判据（评分员数量、锚点/差值设计、听音员筛选、可靠性检验、环境受控、跨次复现），任一不满足即退回内部轨，对齐 CONTEXT.md 双轨测法与不可测四出路框架——见第 5 节。
