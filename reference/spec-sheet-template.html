规格文档与提问清单样张

推导走完之后，评审桌上到底交什么。上半部分是示范机型（室内筒机 · 店铺）的填好样张，下半部分是可照抄的空白模板。形态决议见工单 #14：规格文档取「主表 + 附录」，提问清单取「逐条网格卡」。

一句话

评审桌上只发一页：承诺了什么、凭什么。前提、测法、台账全在附录，答疑时才翻；发给方案商的是另一份投影——每条一张空白网格，「此格无数据」无处可藏。

结构总览

交付物页装什么发给谁
规格文档第 1 页（主表）场景摘要一段 + 分层承诺表（含判据列）+ 双讲组表 + 拾音/放音两个音质节，只留承诺与依据标注，前提用编号上标引用评审桌
附录 A/B前提清单（验证状态四件套 + 喂给哪条）、测法等级绑定表答疑备查
附录 C墙余量表（全量结算输出）+ 退让台账（空是常态）答疑备查
提问清单（选型版）独立成页回答规则前言 + 背景段 + 逐条卡片：问题、回答形状、空白测量网格、口径。不印阈值方案商

为什么主表要瘦：一页塞下全部信息（条款+前提+测法+台账）技术上放得下，但评审的问题是「承诺是否成立」，不是「前提何时验证」——细节上桌反而把讨论拖进执行层。为什么清单要逐条网格：一张总表里「测不了」可以含糊带过，空白格子摆在眼前时，「此格无数据」是显性劣势。

样张 · 规格文档（示范机型：室内筒机 · 店铺）

数据全部来自真实推导（场景参数向量 v1 + 双讲结算拍板）。带 ⚠占位 的格是 SoC 型号未定、预算墙层尚未结算的层——样张如实保留空档，不编数。
